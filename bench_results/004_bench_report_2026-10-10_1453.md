# Benchmark Report 004 — 2026-10-10 14:53 UTC

## Purpose

Establish a corrected benchmark baseline. Search scoring and extraction were
unchanged. Earlier reports accepted filename suffixes and applied different
output budgets across engines, so their percentages are provisional.

## Method

- Archived source and offline lexical index from commit `08fad27`, held fixed
  for both implementations. No LLM requests or index rebuild between runs.
- Same archived 45-query development set for the before/after comparison.
- Corrected run: all seven engines, limit 10, three measured runs and one warmup
  per query/engine, rotating execution order. All engines search indexed files.
- Corpus preparation and index loading are separate from adapter timing.
- Quality uses the first measured output; repeats measure latency. Timing samples
  are pooled for mean/p50/p95. External engines include subprocess startup;
  ctxt runs in process. These are not end-to-end CLI or agent-task timings.
- The grep adapter now executes grep. Both grep and rg use fixed strings and the
  same 1 MiB file cap. Missing tools/command failures are errors, not fast misses.

The corrected ctxt Hit@1 is 30/45 (66.67%), compared with the earlier reported
32/45 (71.11%). Its corrected Hit@3 is 38/45 and Success@10 is 40/45. Baseline
success rates fall substantially when alphabetical output is constrained to the
same budget. Hit@K for those engines describes alphabetical output position,
not relevance ranking.

The current development case file also corrects the CLI-entry-point label to
`cmd/ctxt/main.go`, removes unused per-engine pattern hints, and keeps exact
project-relative labels. It was run separately from the fixed archived-case
comparison above.

The validation questions expose additional ranking gaps. Keep this set frozen;
collect independent queries from other real repositories before generalizing.
Path token estimates count path bytes / 4 only; they do not measure full tool
responses or downstream LLM spending. Noise treats unlabeled paths as irrelevant,
so incomplete relevance labels can overstate it.

## Reproduction

Build and index a frozen checkout, then run:

```bash
ctxt bench --cases docs/bench_cases.json --engines ctxt,find,grep,fd,rg,hybrid,combined --limit 10 --runs 3 --warmup 1 --json
ctxt bench --cases docs/bench_validation_cases.json --engines ctxt,rg,hybrid --limit 10 --runs 3 --warmup 1 --json
```

Install the selected external tools before running. Keep benchmark datasets out
of the indexed corpus when evaluating other projects, so their query text does
not contaminate content results. The current CLI emits report version 2 with
exact matching and explicit success/path-token labels; old JSON field aliases
are not provided.
