Overview

Symbol indexing enhances file discovery by extracting top-level code identifiers (functions, types, classes, constants) from source files and including them as searchable tokens alongside filename and synonym matching.

Problem Solved

Filenames often don't reflect contents. utils.go may contain ParseAuthHeader(), client.ts may have RetryWithBackoff(). Symbol indexing makes these discoverable without full-text search.

Before vs After

Query Before (Filename Only) After (With Symbols)
"JWT validation" Only jwt_*.go or files with JWT synonym Also http_client.go with validateJWTToken()
"retry logic" Only retry*.go Also http_client.go with RetryWithBackoff()
"rate limiting" Only rate_limit*.go Also middleware.go with RateLimitByIP()

Key Design Decisions

  • No full-text search — only declaration lines, keeps index small and fast
  • No LLM calls — pure static analysis, zero API cost
  • No type inference — just names, no resolution
  • No cross-file tracking — not building a call graph
  • Parallel execution — symbol extraction runs alongside synonym generation
  • Backward compatible — omitempty JSON tag for old context files

Data Model

Node Structure

type Node struct {
    FullPath string           // Absolute path on disk
    Type     string           // "file" or "directory"
    Synonyms []string         // LLM-generated + lexical synonyms
    Symbols  []string         // Extracted code identifiers
    Children map[string]*Node  // Child nodes (directories only)
}

symbols.go

Core symbol extraction logic. Dispatches to language-specific extractors based on file extension.

extractSymbols()

Dispatcher function — routes to appropriate extractor based on file extension.

func extractSymbols(path string) ([]string, error) {
    ext := strings.ToLower(path)
    if strings.HasSuffix(ext, ".go") {
        return extractGoSymbols(path)
    }
    if strings.HasSuffix(ext, ".py") {
        return extractByRegex(path, pythonPatterns)
    }
    // ... JS, TS, Rust, Ruby
    return nil, nil  // Unknown extension: no symbols, no error
}

extractGoSymbols()

Uses Go's built-in go/parser package for AST-based extraction. Zero dependencies, perfect accuracy for Go files. 

func extractGoSymbols(path string) ([]string, error) {
    fset := token.NewFileSet()
    f, err := parser.ParseFile(fset, path, nil, parser.AllErrors)
    if err != nil {
        return nil, err
    }
    var symbols []string
    for name := range f.Scope.Objects {
        symbols = append(symbols, name)
    }
    return dedupeStrings(symbols), nil
}

Extracts all top-level declarations: func, type, var, const.

extractByRegex()

For non-Go languages: reads file content and applies regex patterns to extract identifiers. 

func extractByRegex(path string, patterns []string) ([]string, error) {
    content, err := os.ReadFile(path)
    if err != nil {
        return nil, err
    }

    var symbols []string
    for _, pattern := range patterns {
        re := regexp.MustCompile(pattern)
        matches := re.FindAllStringSubmatch(string(content), -1)
        for _, match := range matches {
            if len(match) > 1 {
                symbols = append(symbols, match[1])  // Capture group 1
            }
        }
    }
    return dedupeStrings(symbols), nil
}

tokenizeIdentifier()

Splits CamelCase and snake_case identifiers into searchable tokens. Critical for matching "JWT validation" → validateJWTToken. 

func tokenizeIdentifier(name string) []string {
    var tokens []string

    // 1. Split on underscores
    parts := strings.Split(name, "_")

    for _, part := range parts {
        // 2. Split on camelCase boundaries
        var current []rune
        for i, r := range part {
            if i > 0 {
                prev := rune(part[i-1])
                // lower→upper: "createUser" → "create" + "User"
                if unicode.IsLower(prev) && unicode.IsUpper(r) {
                    tokens = append(tokens, string(current))
                    current = []rune{r}
                // upper sequence→lower: "JWTToken" → "JWT" + "Token"
                } else if unicode.IsUpper(prev) && unicode.IsLower(r) && len(current) > 1 {
                    lastUpper := current[len(current)-1]
                    tokens = append(tokens, string(current[:len(current)-1]))
                    current = []rune{lastUpper, r}
                } // ... digit transitions
            }
            current = append(current, r)
        }
        if len(current) > 0 {
            tokens = append(tokens, string(current))
        }
    }

    // 3. Lowercase and dedupe
    var lower []string
    seen := make(map[string]struct{})
    for _, t := range tokens {
        low := strings.ToLower(t)
        if low == "" || len(low) < 2 {
            continue
        }
        if _, ok := seen[low]; !ok {
            seen[low] = struct{}{}
            lower = append(lower, low)
        }
    }
    return lower
}

indexer.go

Orchestrates index building with parallel synonym generation and symbol extraction.

BuildIndex() Flow

func BuildIndex(opts BuildOptions) (*BuildResult, error) {
    // 1. Build tree from filesystem
    tree, err := BuildTree(absRoot, opts.IgnoredPaths)

    // 2. Collect names for LLM
    names := CollectNamesForLLM(tree)
    missing := missingNames(names, combined)

    // 3. PARALLEL EXECUTION
    var wg sync.WaitGroup
    wg.Add(2)

    // Goroutine A: Synonym generation (LLM, slow)
    go func() {
        defer wg.Done()
        generated, err := GenerateSynonymsForNamesWithContext(...)
        // ... populate combined map
    }()

    // Goroutine B: Symbol extraction (local, fast)
    go func() {
        defer wg.Done()
        count := 0
        walkTree(tree, func(node *Node) {
            if node.Type != "file" {
                return
            }
            syms, err := extractSymbols(node.FullPath)
            node.Symbols = syms
            count++
        })
        symbolCount = count
    }()

    // 4. Wait for both
    wg.Wait()

    // 5. Assign synonyms
    AssignSynonymsToTree(tree, combined, opts.SynonymsPerName)

    // 6. Return result
    return &BuildResult{Index: index, Stats: stats, ...}
}

search.go

Implements search scoring with symbol matching.

SearchHintsWithOptions()

func SearchHintsWithOptions(index *ContextIndex, query string, opts SearchOptions) []SearchResult {
    // 1. Tokenize query
    tokens := tokenize(query)  // "JWT validation" → ["jwt", "validation"]

    // 2. Walk tree and score each node
    walkTree(index.Tree, func(node *Node) {
        score := 0
        matches := []string{}
        breakdown := []string{}

        for _, token := range tokens {
            // ... filename/path scoring ...

            // Synonym scoring
            for _, syn := range node.Synonyms {
                if synLower == token {
                    score += 8  // Exact synonym match
                }
            }

            // Symbol scoring (NEW)
            for _, sym := range node.Symbols {
                symLower := strings.ToLower(sym)
                symTokens := tokenizeIdentifier(symLower)

                if symLower == token {
                    score += 8  // Exact symbol match
                    matches = append(matches, "sym-exact:"+sym)
                } else if strings.Contains(symLower, token) {
                    score += 5  // Symbol contains token
                    matches = append(matches, "sym:"+sym)
                }

                // Tokenized parts (camelCase split)
                for _, symToken := range symTokens {
                    if symToken == token {
                        score += 4  // Tokenized symbol part
                        matches = append(matches, "sym-token:"+symToken)
                    }
                }
            }
        }

        // 3. Build result
        results = append(results, SearchResult{Path, Type, Score, Matches, Breakdown})
    })

    // 4. Sort and return
    sort.Slice(results, func(i, j int) bool {
        return results[i].Score > results[j].Score
    })
    return results
}

node_mutation.go

Handles file system changes (create, write, remove) and keeps the index in sync.

upsertNodeByRelPath()

func upsertNodeByRelPath(root *Node, absRoot string, relPath string, isDir bool, ...) bool {
    changed := false

    // ... navigate to parent ...

    node, ok := parent.Children[name]
    if !ok {
        // CREATE: new node
        var symList []string
        if !isDir {
            symList, _ = extractSymbols(fullPath)  // Only for files
        }
        parent.Children[name] = &Node{
            FullPath: fullPath,
            Type:     nodeType,
            Synonyms: nodeSynonyms,
            Symbols:  symList,  // Attach symbols
            Children: make(map[string]*Node),
        }
        return true
    }

    // UPDATE: existing node
    if node.Type != nodeType {
        node.Type = nodeType
        changed = true
        if nodeType == "directory" {
            node.Symbols = nil  // Clear symbols if converted to dir
        }
    }

    if node.Type == "file" {
        symList, _ := extractSymbols(fullPath)
        if !stringSlicesEqual(node.Symbols, symList) {
            node.Symbols = symList
            changed = true  // Mark changed if symbols differ
        }
    }

    return changed
}

Language Support

Symbol extraction supports multiple languages via AST (Go) or regex patterns (others).

Supported Languages

Language Extensions Method Patterns

Python .py Regex ^(?:async\s+)?def\s+(\w+)
^class\s+(\w+)
JavaScript .js, .mjs Regex ^(?:export\s+)?(?:async\s+)?function\s+(\w+)
^(?:export\s+)?class\s+(\w+)

^(?:export\s+)?interface\s+(\w+)
^(?:export\s+)?type\s+(\w+)
^(?:export\s+)?enum\s+(\w+)
Rust .rs Regex ^(?:pub\s+)?fn\s+(\w+)

^enum\s+(\w+)
^trait\s+(\w+)
^impl\s+(?:[^<]*<)?(\w+)
Ruby .rb Regex ^def\s+(\w+)
^class\s+(\w+)
^module\s+(\w+)
Regex Limitations

Regex-based extraction may miss edge cases: multiline declarations, comments, unusual formatting. Go AST extraction is 100% accurate. For other languages, regex covers ~90% of common patterns.

Ignore System

Ignore patterns are applied in layers to prevent indexing unwanted files and protect against crashes.

Ignore Layers (Applied in Order)

  1. Hard-coded defaults (ignore.go:8-35) — Always active
  2. Project .gitignore — Loaded automatically
  3. Config file — ignore array in config.toml
  4. CLI flag — --ignore for ad-hoc patterns

Performance

Benchmarks

Operation Time Notes
Build tree (1000 files) ~50-100ms Filesystem walk, I/O bound
Synonym generation (100 names) ~500-2000ms Network bound, batched LLM calls
Symbol extraction (1000 files) ~100-500ms I/O bound, parallel with synonyms
Search query ~5-20ms In-memory tree walk, no I/O
File change (upsert) ~1-5ms Single file symbol extraction

Optimization Strategies

  • Parallel execution — Symbol extraction runs alongside synonym LLM calls, saving ~100-500ms on large repos
  • Index-time extraction — Symbols extracted once at build/change time, not per search
  • In-memory search — Full tree in memory, no disk I/O during search
  • Graceful degradation — Parse errors silently skipped, don't crash or block

Memory Usage

Symbol storage adds ~100-500 bytes per file to context.json. For 1000 files: ~100-500KB additional. Negligible for modern systems.

Thread Safety

Parallel Execution in BuildIndex()

var wg sync.WaitGroup
wg.Add(2)

// Goroutine A: writes to `combined` map and `synonymErr`
go func() {
    defer wg.Done()
    for name, values := range generated {
        combined[name] = sanitizeSynonyms(values, ...)  // Safe: unique keys
    }
}()

// Goroutine B: writes to `node.Symbols` and local `count`
go func() {
    defer wg.Done()
    walkTree(tree, func(node *Node) {
        node.Symbols = syms  // Safe: each node unique
        count++  // Safe: local variable
    })
}()

wg.Wait()

// Main thread: reads `combined`, writes `node.Synonyms`
AssignSynonymsToTree(tree, combined, ...)

Why It's Safe

  • No shared writes — Goroutine A writes combined map, Goroutine B writes node.Symbols. Different data structures.
  • Unique keys — Each goroutine operates on unique keys (map keys for A, node pointers for B).
  • WaitGroup synchronization — AssignSynonymsToTree() runs only after both goroutines complete.
  • No mutex needed — No concurrent writes to same memory location.
Search is Read-Only

SearchHintsWithOptions() only reads from the index. Safe to call concurrently from multiple goroutines.

Troubleshooting

Safety Features

Hard-Coded Default Ignores

Certain paths are always ignored, regardless of .gitignore presence. This prevents crashes on projects missing .gitignore. 

// ignore.go - ALWAYS active
defaultIgnores = [
    // Version control
    ".git", ".svn", ".hg",
    // Dependencies (critical - can crash indexer)
    "node_modules", "vendor", "bower_components",
    // Virtual environments
    ".venv", ".cache", ".pytest_cache", "site-packages", "__pycache__",
    // Build outputs
    "dist", "build", "out", "tmp", "temp",
    // IDE
    ".vscode", ".idea",
    // OS junk
    ".DS_Store", "Thumbs.db",
]

File Count Safety Limit

Indexing stops if file count exceeds safety threshold to prevent memory exhaustion.

Threshold Action Message
5,000 files Warning logged Large repository detected (5000 files). Consider adding more ignore patterns.
10,001 files Hard error — build stops file count exceeds safety limit (10000 files). Add more patterns to .gitignore or use --ignore flag

Default limit: MaxFileCount = 10000 in node.go:26. Adjust if needed for legitimate large repos.

Common Issues

Index build fails with "file count exceeds safety limit"

  • Cause: Repository has >10,000 files after applying ignore patterns
  • Fix: Add more patterns to .gitignore or use --ignore flag
  • Example: contexting build --ignore "generated" --ignore "*.min.js"
  • Override: Edit MaxFileCount in node.go:26 (not recommended)

Symbols not appearing in search results

  • Check: Run contexting build and verify console shows "✓ Extracted symbols from N files"
  • Check: Inspect context.json — do file nodes have "symbols" field?
  • Check: Is the file extension supported? (Go, Python, JS/TS, Rust, Ruby)
  • Check: Are symbols top-level? Nested functions/classes not extracted.

Search scores seem wrong

  • Debug: Use --debug flag to see score breakdown
  • Check: Tokenization — run tokenizeIdentifier("YourSymbol") to see how it splits
  • Check: Query tokenization — "JWT validation" becomes ["jwt", "validation"]

Build fails with parse errors

  • Go files: go/parser errors indicate syntax errors in source
  • Other languages: Regex extraction is lenient — malformed files may return empty symbols but won't crash
  • Check: File permissions — can the process read the source files?

Index not updating on file changes

  • Check: Is watch mode running? contexting watch
  • Check: File path — is it within the indexed root?
  • Check: Ignored paths — is the file/directory in .contextignore?
